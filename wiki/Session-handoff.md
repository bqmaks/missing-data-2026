# Продолжение в следующей сессии

Снимок состояния на **2026-11-24, Europe/Moscow**. Подготовлен по просьбе пользователя. Новую задачу определяет следующее поручение; перечисленные ниже направления — открытые вопросы, а не утверждённый план их автоматического выполнения.

## С чего начать

1. Прочитать корневой `AGENTS.md`, [Decisions.md](Decisions.md), [Lecture-plan.md](Lecture-plan.md) и новое поручение пользователя.
2. Проверить `git status --short` и историю: файлы могли меняться после этой записи. На момент подготовки единственный посторонний незакоммиченный файл — `snowflake.log`; не включать его в изменения курса и не удалять.
3. Перед работой над содержанием заново прочитать актуальные файлы `course-inputs/`, включая её `AGENTS.md`. Папка игнорируется Git и может меняться без участия агента. Проверка списка и контрольных сумм:

```bash
rg --files --hidden --no-ignore course-inputs/
sha256sum -c wiki/Input-fingerprints.sha256
```

Контрольные суммы отражают состояние при подготовке этой записи, а не заменяют чтение файлов. Новые файлы обнаруживаются отдельным перечислением. История R в `course-inputs/.Rhistory` в снимок не включена; её содержимое не нужно для продолжения курса.

## Что осталось открытым

1. **Нелинейный SMC-FCS, модуль 6.** DGP seed 3001, SMC seed 63; при m = 20, 20 итерациях и rjlimit = 100000 осталось 27 отказов rejection sampling. Причина не установлена. Простое повышение лимита не решило проблему и удлинило расчёт. `smcfcs_checked()` сохраняет предупреждения и исключает такую оценку из итоговой таблицы. В `static/data/part3.json` ненадёжной строки SMC-FCS нет; диагностика сохранена. Не возвращать её до устранения отказов. Пример Кокса при тех же m / итерациях / лимите прошёл без таких отказов.
2. **Авторская проверка 12 слайдов:** v2:17, 54, 61, 72, 73, 77, 80, 82–85, 87. В [Open-questions.md](Open-questions.md) сохранены исходные пометки: часть из них говорит «код не запускался» о состоянии первоначального PPTX. Фактические последующие запуски и проверенные API описаны в Validation.md; это не заменяет подтверждение научных тезисов автором.
3. **Численные примеры PPTX:** LOCF, РКИ, зависимость от корреляции, EM и другие отмеченные примеры ещё не воспроизведены единым R-расчётом. В слайдах есть предупреждения; не выдавать их числа за предрасчёты проекта.
4. **Иллюстративная выборка:** используется фиксированный seed 202601 без отбора по результатам; требование входных инструкций о подборе «типичной» выборки не выполнено и оставлено для обсуждения.
5. **Учебная редактура и тайминг:** нужна обратная связь по первой версии и репетиция трёх занятий с практикой. Объём самостоятельной работы ещё не определён. При необходимости интерактивов сначала выбрать конкретную учебную задачу.

## Что не потерять при следующих правках R

- Матрица предикторов в модуле выживаемости задаётся **до** инициализации mice: иначе H Нельсона–Аалена исключался как почти коллинеарный time. Сейчас есть проверка, что H используется, а time — нет. Для smcfcs передаётся исходный d7 без добавленного H.
- В расширенной когорте занятия 2 исходный механизм пропусков глюкозы зависит от частично скрытого истинного ИМТ; он не объявляется строгим MAR. Пассивная схема ИМТ задаётся до сравнения norm/pmm, проверяются согласованность ИМТ и доноры PMM.
- Полный прогон занятия 3 выполнен с бутстрепом 200 × 2; затем исправленный mice-пример выживаемости пересчитан отдельно и обновлён в предрасчёте. Ненадёжная нелинейная SMC-оценка исключена. Защита проверена коротким реальным прогоном при m = 2, 2 итерациях, rjlimit = 10.
- Дополнительные ветки NHANES и Amelia не запускались. Наличие диагностик не доказывает сходимость или корректность модели.
- `outputs/` и `/tmp` не версионируются: не рассчитывать на их наличие в следующей среде. Экспорт специальных примеров требует заново получить актуальные `outputs/part2-results.rds` и `outputs/part3-results.rds`.

## Команды и среда

Обычная сборка не требует входной папки, R или npm install:

```bash
python3 scripts/build_deck.py
quarto render index.qmd --to material-revealjs
```

В ограниченной среде запись стандартного кэша Quarto не работала; использовалось:

```bash
XDG_CACHE_HOME=/tmp/missing-data-quarto-cache quarto render index.qmd --to material-revealjs
```

Практика запускается из корня проекта: `Rscript missing_data_practice.R 1` (также 2 или 3); проверка статистики — `Rscript tests/validate_statistics.R`. Установка зависимостей явно выполняется через `scripts/install_packages.R`. Полный SMC-FCS может занимать десятки минут; повторять долгие расчёты только при необходимости.

В текущей среде проверены Quarto 1.10.18, R 4.6.1, mice 3.19.0, smcfcs 2.0.3, bootImpute 1.3.0, MatchThem 1.2.1. Временные дополнительные R-пакеты находятся в `/tmp/missing-data-r-lib`; при их наличии используется префикс `R_LIBS=/tmp/missing-data-r-lib`.

Для браузерной проверки при сохранении временных инструментов:

```bash
NODE_PATH=/tmp/missing-data-tools/node_modules \
CHROME_PATH=/home/bqmaks/.cache/puppeteer/chrome/linux-156.0.8078.47/chrome-linux64/chrome \
DECK_URL=https://bqmaks.github.io/missing-data-2026/ \
node scripts/check_deck.cjs
```

Без `DECK_URL` проверяется локальный сервер `http://127.0.0.1:8765/`; запуск: `python3 -m http.server 8765 --bind 127.0.0.1 --directory _site`. Наличие инструментов и сервера нужно проверить заново. Браузер и сетевые команды в прежней среде требовали выхода за ограничения песочницы.

После существенного изменения наполнения раскладку строить только из **неразбитой** версии: `build_deck.py --unpaginated` → Quarto → `scripts/layout_deck.cjs` на локальном сервере → обычная сборка → проверка браузером. Не запускать измерение раскладки поверх уже разбитых экранов.

Push в `main` запускает сборку и публикацию Pages. Проверять результат Actions и, после изменений презентации, публичную версию. Общий шаблон в этой сессии не менялся.
