# Анализ данных с пропусками в биостатистике

Первая редакция материалов для [курса Института биоинформатики](https://bioinf.me/education/stat): три занятия по 90 минут, HTML-презентация и практика на R.

## Открыть материалы

[Презентация на GitHub Pages](https://bqmaks.github.io/missing-data-2026/) · [Режим чтения](https://bqmaks.github.io/missing-data-2026/reading.html) · [R-файл](https://bqmaks.github.io/missing-data-2026/downloads/missing_data_practice.R)

После сборки откройте `_site/index.html`. Рекомендуемый просмотр через локальный сервер:

```bash
python3 -m http.server 8765 --directory _site
```

Адрес: `http://localhost:8765`. Все шрифты, формулы и иллюстрации локальные. Режим чтения с полными заметками — `_site/reading.html`.

- Стрелки / пробел — следующий экран; `O` — обзор; `F` — полный экран.
- `D` — включить углублённые и справочные слайды; по умолчанию только основная линия.
- `N` — заметки докладчика. Кнопка «Чтение» открывает вертикальную версию для самостоятельной работы и печати.
- [Самостоятельный R-файл](downloads/missing_data_practice.R) работает без других файлов проекта.
- [ZIP практикума](downloads/missing-data-practice.zip) содержит модули, общий DGP и предрасчёты.

Из исходной презентации сохранены все 89 слайдов. Плотные слайды разделены на продолжения, поэтому экранов HTML больше. Соответствие — [traceability.csv](wiki/traceability.csv).

## Запустить практику

Требуется R ≥ 4.3. Установить зависимости один раз:

```bash
Rscript scripts/install_packages.R
```

Запуск из корня проекта:

```bash
Rscript missing_data_practice.R 1
Rscript missing_data_practice.R 2
Rscript missing_data_practice.R 3
```

Можно открыть соответствующий файл `practice/practice_part1.R`, `practice_part2.R` или `practice_part3.R` в RStudio и выполнять блоки последовательно. Каждый файл самостоятельно загружает общие функции. Результаты и диагностические PDF сохраняются в `outputs/`.

Самостоятельный файл `downloads/missing_data_practice.R` принимает тот же номер занятия. В RStudio номер задаётся переменной `lesson` в начале файла. Зависимости устанавливаются явно; скрипты не устанавливают пакеты автоматически.

Дополнительный бутстреп (модуль 8) включается перед запуском третьей части:

```r
options(missingdata.bootstrap = TRUE, missingdata.nBoot = 200L)
source("practice/practice_part3.R")
```

Полный расчёт SMC-FCS в третьем занятии может занимать десятки минут: его стоит выполнить до занятия. Увеличенный `rjlimit` нужен для корректного розыгрыша крайних значений; предупреждения алгоритма необходимо разбирать. Для знакомства с интерфейсом можно уменьшить `missingdata.m` и `missingdata.maxit`, но такой запуск не подтверждает сходимость или точность итогового анализа.

В первой редакции нелинейный пример SMC-FCS сохраняет 27 отказов rejection sampling при полном проверенном запуске. Скрипт явно сообщает об этой проблеме и исключает такую оценку из итоговой таблицы. Проверенный пример Кокса прошёл без этих отказов.

## Пересобрать презентацию

Требуются Quarto 1.10.18 (проверенная версия), Python 3 и Node.js. KaTeX и расширение Material включены в репозиторий; `npm install` для сборки не нужен.

```bash
python3 scripts/build_deck.py
quarto render index.qmd --to material-revealjs
```

`index.qmd` и `reading.html` генерируются из `slides/source-deck.json`, `slides/layout.json` и кода редакционных изменений в `scripts/build_deck.py`. Исправления нужно вносить в эти источники, иначе следующая генерация их перезапишет.

Предрасчёты уже включены в `static/data/`. Для обновления чисел:

```bash
Rscript scripts/precompute.R
Rscript tests/validate_statistics.R
python3 scripts/build_deck.py
quarto render index.qmd --to material-revealjs
```

Обновлённые таблицы покрытия: 2000 репликаций, n = 500; рядом с долями указан MCSE. Для быстрой работы в аудитории используется 300 репликаций с явно напечатанной ошибкой Монте-Карло.

Входные файлы в `course-inputs/` могут меняться независимо и исключены из Git. Повторный импорт выполняется **явно**, после чтения новых файлов:

```bash
python3 scripts/import_course.py
```

После изменения содержания проверить раскладку: собрать с `python3 scripts/build_deck.py --unpaginated`, отрендерить, выполнить `scripts/layout_deck.cjs` с Playwright на локальном сервере, затем собрать обычным способом. Этот процесс сохраняет всё содержание и разбивает плотные слайды по границам блоков и абзацев.

## GitHub Pages

Workflow `.github/workflows/pages.yml` собирает и публикует `_site/` после push в `main` или ручного запуска. В репозитории выбран источник **GitHub Actions**. Для сборки не нужны локальные входные файлы и установка R. Результаты проверок — в [Validation.md](wiki/Validation.md).
